- 项目没有 `robot.ts`；相应职责位于 `src/robot/model.ts`、`bones.ts`、`fallback.ts`。
- `public/models/` 当前只有 README，没有 `robot.glb`。加载器在资源缺失时启用内置机器人。
- 内置机器人通过真正的 `THREE.Bone` 节点驱动挂在骨骼下的刚性几何体，有 17 根骨骼、独立肩肘结构；它不是导入的蒙皮 GLB。
- 已运行 `createFallbackRobot()` 和 `collectBones()`，确认下表层级和初始变换。此次检查为 Node 对项目模型代码的实例化检查，不是新一轮浏览器或真机验收。
- `collectBones()` 保存初始位置、四元数、缩放；`resetBones()` 可按保存值复位。当前 UUID 只适合本次加载中定位，不适合持久化映射配置。
- `StudioScene` 已有独立渲染循环，但尚无动作更新回调。手动滑块直接写骨骼旋转，需要明确跟随模式下的控制权。
- 第二阶段 `PoseFrame` 分离 `normalizedLandmarks` 与 `worldLandmarks`，尚无序号和时间戳。`src/mobile/main.ts` 在摄像头回调内推理和绘制，尚无可复用订阅入口。
- 机器人页面和 `pose.html` 为两个独立入口；第三阶段采用同页识别和驱动，不默认具备手机到电脑的远程通信。

## 3. 模型依赖和实施边界

建议先用已有程序化骨架完成双上臂模拟验证和摄像头接入。它已具备所需独立关节，无需为了启动算法开发更换模型。

需求中的“实际 GLB 骨骼列表与驱动验收”目前缺少资产，必须保留为未完成项。后续提供有使用授权的 `public/models/robot.glb` 后，重新检查其实际骨架、静止姿态和轴向，再建立专属配置；不得把当前名称应用到任意 GLB。

如果需要沿用现有外观而交付 GLB，可另行选择将自有程序化模型制作成具有适当骨架/蒙皮结构的 GLB；简单导出带名字的普通节点不保证导入后仍被识别为 Bone。该资产制作不混入本次准备。

第一批实现左右上臂；第二批接入识别；独立前臂映射随后增加。躯干保留配置接口，腿、全身 IK、根位移、跨设备通信不在本阶段首批范围。

## 5. 输入、坐标和映射配置

- 保留现有 PoseFrame 结构，适配出 `{timestampMs, seq, source, coordinateSpace, worldLandmarks}`。时间使用本地单调时钟，序号按采集会话递增；重启时清除上一会话状态。
- 使用世界坐标计算相对方向。官方定义其单位为米、原点为髋部中点；不把推断坐标当作精确测量值，不将归一化图像坐标作为缺失时的静默替代。
- 每条骨骼链独立检查所需端点的存在性、有限数值、可见度和长度。初版可见度阈值沿用 0.5；零长度、NaN、Infinity 和过期/乱序帧拒绝更新。
- 坐标转换集中在适配器，拟采用 `(x, -y, -z)` 转入 +Y 向上、+Z 朝观察者的显示空间；这是待用真实姿态验证的应用约定，不能仅凭世界坐标单位就认定轴向已验证。用单侧抬臂、前伸及侧身确认符号。
- 前摄镜像仅作用于视频/叠加展示，不修改原始输入、不交换解剖左右；后摄、镜头切换、浏览器提供的原生变焦能力继续复用第二阶段实现。
- 每个模型配置明确来源及骨骼路径、末端路径、参考方向、初始局部旋转、轴修正、扭转参考轴和限制。路径含同名节点区分信息；运行时再解析为骨骼引用。
- 不存在、重名不明确或链关系错误时显示具体警告并禁用对应链，其余功能继续运行。未知 GLB 不按相似名字自动绑定。

## 6. 方向求解及稳定性

1. 初始化时保存静止姿态，更新模型世界矩阵，解析骨骼及参考方向；每帧复用向量/四元数和已有模型。
2. 将人体肩→肘方向转入约定的目标空间，再通过父节点当前世界旋转的逆变换转到父空间。模型根节点旋转也必须包含在转换中。
3. 以上臂静止方向求 swing，再相对保存的初始四元数组合目标局部旋转。首版约束 twist，明确为“手臂方向跟随”，不宣称恢复完整肩关节姿态；方向接近反向时使用固定参考轴和连续性处理，避免任意翻转。
4. 在静止姿态坐标系中限制 swing/twist，按模型配置设定保守范围。肘部若启用，使用独立弯曲轴及角度范围。只对四元数转成 Euler 再逐项截断不作为通用限位方案。
5. 初版支持正的均匀缩放骨架。存在负缩放、非均匀缩放或剪切时标记不支持并停用对应链；不能只取父四元数就声称支持这些变换。
6. 按父到子顺序求解；启用前臂后，基于本帧实际应用的上臂旋转更新父世界矩阵，再求前臂，避免使用过时矩阵。
7. 平滑系数使用时间步长，例如 `1-exp(-dt/tau)`；时间常数初值约 0.12 秒，按实际观感调整。渲染每帧继续平滑，只有新识别帧更新有效时间，不能重复消费同一帧来刷新“仍在跟踪”。
8. 单条链低置信度时先保持约 250ms，随后平滑回到保存的初始姿态；这些是待调参数。长时间停帧也触发恢复。恢复到足够小误差后精确拷贝初始姿态。
9. 暂停跟随保持当前姿态；重置清除目标/滤波状态、恢复初始位置/旋转/缩放，并暂停跟随，避免下一帧立刻覆盖复位。手动调节必须退出跟随，UI 不显示过期滑块值。

## 7. 页面与生命周期

- 新增同页动作映射入口：默认模拟输入，用户主动启动摄像头后再初始化 MediaPipe 和申请权限。
- 复用一个采集会话、一套识别循环和一个机器人渲染循环；摄像头采集与渲染各有职责，不在推理回调重建模型。
- 调试界面显示两侧所需点及置信度、输入时间、方向向量、实际骨骼路径、目标/当前四元数或角差、跟踪/保持/回中状态。
- 模拟场景包含左右独立运动、双臂外展/前伸、单侧丢点、低置信度、无输入、反向向量；允许暂停、重置和切换输入。
- 切换输入源、镜头、停止、后台和卸载时清理旧输入；复用第二阶段授权异步返回及资源释放防护，防止旧会话覆盖新会话。
- 手机浏览器同时运行推理和 WebGL 的性能需实际测量；桌面模拟结果不能替代真机功耗、相机关闭或持续运行验收。

## 8. 实施与验收顺序

1. 先完成实际骨架配置和双上臂模拟驱动，检查左右独立、静止方向和父变换正确性。
2. 验证零长度/非有限值/反向向量、重复旧帧、乱序、不同帧率、丢失后恢复、精确重置；使用非单位初始四元数和旋转父节点的测试骨架，防止只适用于当前零旋转模型。
3. 完成调试页、渲染更新接口和控制权切换，再提取采集会话并接入第二阶段真实输出。
4. 执行 `npm run typecheck`、`npm test`、`npm run build` 和已有两阶段浏览器回归，新增映射页窄屏、切源、停止/重启及单模型实例检查。
5. 在真实手机上使用后摄验证左/右抬臂、前伸、低置信度恢复及支持设备的变焦；持续运行至少 5 分钟记录推理与渲染帧率、设备和浏览器。未执行项如实保留。
6. 用户提供 GLB 或确定资产制作路径后，执行实际 GLB 的层级检查和专项绑定验收；测试夹具不替代交付资产。
7. 实施完成并通过检查后，提交并同步既有 GitHub 仓库，使用既有 SSH 密钥和部署脚本发布至当前服务器，保留回滚版本；核对线上版本与 GitHub 提交、CI 结果。

本次准备只增加方案文档；不将尚未实现的功能作为新版本部署。
