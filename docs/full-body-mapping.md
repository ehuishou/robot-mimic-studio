# 全身映射交付与验证（2026-10-24）

## 当前交付

实际资产 public/models/robot.glb 为本项目生成的蒙皮模型：17 根骨骼、1 个网格、5 种材质。本轮无需替换 GLB。robot.mapping.json 的 v2 配置保留 14 组映射，新增可选 motion 元数据，通过 hipsPath 与 expectedHipsName 核验骨盆。未知模型必须独立配置，不能按名字猜测。

| 部位 | 输入与处理 | 驱动 |
| --- | --- | --- |
| 骨盆 | 左右髋线、髋到肩的上方向形成旋转基，四元数连续插值 | Hips 完整转身 |
| 胸腰 | 肩线形成胸腔朝向，转换到骨盆父坐标系 | Spine，Chest 继承，允许相对骨盆扭转 |
| 头颈 | 眼点 2/5 与嘴角 9/10 形成脸部旋转基 | Neck，Head 继承 |
| 上臂/前臂 | 肩肘腕方向及可观测弯曲平面 | UpperArm / Forearm |
| 手 | 腕到粗略手部关键点及掌面法向 | Hand，无手指骨骼驱动 |
| 大腿/小腿 | 髋膝踝方向及可观测弯曲平面 | UpperLeg / LowerLeg |
| 脚 | 踝到脚尖方向；接触时固定世界位置及朝向 | Foot，加双骨骼腿部 IK |

旧头颈算法使用肩中心到鼻点的方向，鼻部的前伸偏移容易变成持续低头。增强模式已改用脸部旋转基，与脚锁定、身体高度求解分开。脸部不可见时短暂保持，250ms 后颈部回到局部中立并继承躯干朝向。

## 位移与脚锁定

MediaPipe 世界关键点以人体髋部为中心，不能单独恢复场景位移。采集端另外从归一化图像关键点提取髋中心 x/y 与躯干 scale，经校验后的可选 motion 字段随关键点通过 WebSocket 转发。中继和接收端都保留该字段；旧消息仍可驱动关节。

第一帧有效摘要建立参考。横向位置与躯干尺度变化近似估算左右和远近位移，分别限制在 ±2.5、±2 场景单位；持续突跳被拒绝，不靠等待自动接受异常值。站立/蹲下高度参考最低脚踝求解，不模拟跳跃。暂停冻结姿态和位移，重新定位清除位置参考并释放脚锁，重置恢复初始骨架和位置。

低速、低抬脚高度且稳定至少 160ms 后建立脚部世界锚点，通过双骨骼 IK 修正腿部，保持骨长。抬脚、快速运动、脚朝向改变、锚点过远、不可达、识别超时、暂停、重新定位和关闭开关时释放。锁定目标为初始地面上的脚骨骼位置，保持初始鞋底到脚骨骼的偏移。

## 配置、求解与保护

- 绑定依赖 children 索引路径、预期名称和直接父子关系；正均匀缩放才启用。motion 配置无效时回退基础方向映射并提示。
- 输入按 (x,-y,-z) 转场景，父节点先更新，目标世界四元数转换到当前父坐标系。使用时间相关 SLERP，避免欧拉角跨 ±180° 跳变。
- 四肢保持原有方向摆角限位，并恢复可观测轴向旋转；增强模式骨盆/胸颈使用完整朝向，不使用旧的中心段方向摆角限位。
- 低置信度、非有限坐标、退化旋转基不形成新观察。250ms 无有效观察后恢复；末端脚锁同步释放。
- 手机暂停/重置保留 capture session，继续使用新帧，无需重开手机识别。停止或断线结束对应会话。
- 不上传相机画面，仅发送关键点及位置摘要。

## 使用

1. 电脑打开 /mapping.html，先用“连续转身”“胸腰扭转”“人物位移”“站立锁脚”检查效果，也保留全身与迈步演示。
2. 选择本机摄像头，或创建配对后在手机打开链接并启动识别。
3. 固定后置摄像头，让头部到脚尖完整入镜，站稳开始。更换镜头、变焦或移动摄像头后点击“重新定位”。
4. “脚底锁定”可随时关闭；暂停后点继续不需要重新启动仍在运行的手机采集。
5. 三个页面底部的 GitHub 图标在新标签页打开项目仓库，私有仓库内容需要 GitHub 访问权限。

## 限制与真机待验收

单摄像头的深度和转身观测存在歧义；侧身、背身、遮挡、四肢伸直时不能保证所有旋转准确。位移依赖固定镜头、身体尺度近似和地面支撑假设，不是米制轨迹；蹲下、俯身可能影响远近估计。脚锁为接触启发式，不含地形碰撞、动力学或精确足底压力。不追踪手指。

上述自动化使用合成关键点与模拟摄像头，不能替代实际手机。仍需记录具体手机/浏览器、光照、网络、后摄动作精度、遮挡恢复、温升/内存、10 分钟运行和端到端 P95 延迟。
