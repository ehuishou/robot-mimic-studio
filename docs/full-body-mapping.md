## 求解与安全

- 在真实 GLB 上遍历骨骼，由 JSON children 索引路径 + 预期名称 + 直接父子关系确认绑定，不根据名字猜测未知模型。
- 参考向量来自直接子骨骼初始位置；末端 Hand/Foot 使用配置明确给出的本地参考方向。
- 输入差向量按 `(dx,-dy,-dz)` 转换，再应用配置轴修正。按骨骼深度由父到子求解，将世界方向变换到当前父坐标系，使用最小摆动和初始四元数生成目标。
- 保留摆角限位、近反向方向稳定轴、时间相关 SLERP、有限坐标/置信度/序号/时间校验。250ms 无有效观察后平滑回中，不允许旧观察维持永远跟随。
- 骨骼链仅支持正的均匀缩放；非均匀缩放、负缩放、剪切和错误配置停用并提示，不污染模型。
- 手机模式暂停/重置只清除待处理帧，保留有效 capture session；继续时只消费新的帧。手机停止/离线/切换来源才结束对应会话。WebSocket 只传关键点，不上传摄像头画面。

## 使用

1. 打开电脑 `/mapping.html`，选择“全身动作”“迈步动作”先验证模型；“骨架与方向”打开输入/实际方向辅助线，观察面板有 14 组状态。
2. 本页用相机时选择“本机摄像头”；跨设备时点“创建手机配对”，用手机打开链接并启动识别。
3. 使用后置摄像头，手机固定，人体头部到脚尖完整入镜；先做抬臂、弯肘、抬膝、侧倾和点脚，避免遮挡。可用镜头和原生缩放由设备能力决定，不保证任意光学焦段。
4. 电脑暂停/重置后点“继续跟随”，无需重启仍在运行的手机采集。停止采集后应回中。

## 明确限制与真机待验收

当前是关节方向近似：不解算人体完整旋转，不恢复轴向扭转、肩线 roll 或骨盆/胸腔转身朝向；鼻点只近似头颈方向。没有根位移、手指、脚底锁定、地面接触或物理行走。关节可能在限位处与人体不同，迈步姿态可能抬脚或穿地。

自动化发送端与模拟摄像头不是实际手机。仍需记录具体手机/浏览器、网络与光照，验证后摄人体动作精度、遮挡恢复、温升/内存、10 分钟运行，以及端到端 P95 延迟。未记录这些证据前不宣称完成全部真机验收。
