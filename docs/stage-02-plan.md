## 实现约定

### 摄像头与生命周期

- 由用户点击开始触发初始化，摄像头优先请求 `facingMode: ideal user`，不开启音频；视频使用 `muted`、`autoplay`、`playsinline`。
- 启动前检测安全上下文与摄像头 API。权限拒绝、设备缺失、被其他应用占用、初始化失败等分别提示可执行的处理方式。
- 使用 idle / starting / running / stopping / error 状态；识别结果状态单独表示等待人体、低置信度或已识别。
- 每次启动分配会话代号，异步返回时核对代号。停止后才返回的摄像头流立即停止，延迟完成的推理实例立即释放，防止点击停止后又重新开机。
- 任一启动阶段失败都清理已分配资源；停止操作幂等，取消帧回调、停止所有 tracks、清空 `srcObject`、关闭推理实例、清空骨架与统计。
- `pagehide`、页面销毁和 HMR 执行清理。进入后台时停止摄像头；返回页面显示可重新启动状态，不自动重开摄像头。
- 只有一个有效推理循环；多次点击、停止后重启和浏览器往返都不能遗留旧循环或重复事件监听。

### 推理和绘制

- 采用单人、视频模式。优先按视频帧回调驱动，使用 RAF 时比较视频时间，跳过未更新的帧；提交单调递增的时间戳。
- 等待视频元数据和有效图像尺寸后推理。先完成主线程正确实现，再依据手机测量决定是否需要 Worker。
- 分开记录 `landmarks` 与 `worldLandmarks`；绘制只使用归一化图像坐标，保留原始左右语义供后续阶段使用。
- 前置镜像只作用于视频与画布的显示，不改写原始姿态数据；保持相同的裁切、比例与镜像，避免骨架错位。
- 结果数组、人数和每个关键点都先检查。低置信度点不绘制，与其相连的线也不绘制；无人时清除上一帧骨架。
- 显示实际返回关键点数及有效点数，区分返回 33 个点与 33 个点都可靠；阈值集中配置。
- FPS 仅统计真实完成的推理次数，不使用渲染帧率代替。异常中断时归零或显示无数据。
- 画面只在本地浏览器处理，不加入上传、录制或遥测。

### 模型与 WASM

- 同源提供模型和 WASM，避免运行时依赖未锁定的 CDN 路径；WASM 配套文件来自与 JS 相同的锁定包。
- 资源脚本校验模型内容/哈希并在失败时退出，不能将 HTML 错误响应当作模型，也不能带着缺失资源继续发布。
- 资源路径基于 Vite base，验证默认根路径和子路径构建；构建产物必须包含所需资源。
- README 仅记录实际采用的来源和文件；本准备文档中的拟定路径不是下载完成证明。
