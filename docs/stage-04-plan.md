## 2. 本阶段范围和页面流程

手机（本地识别） → 同源 WSS 中继 → 电脑（已有 Three.js 动作映射）。

1. 电脑在 `mapping.html` 选择“手机远程输入”，主动创建配对，显示连接状态与手机配对链接。
2. 手机通过链接打开 `pose.html`，注册 mobile；连接成功后由用户启动摄像头。保留后摄、具体镜头、设备原生变焦；识别和预览继续在手机本地进行。
3. 手机发送世界坐标点；电脑注册 viewer，显示对端在线、采集状态、最近收帧时间、有效接收帧率及丢帧计数。
4. 同机模拟、同机摄像头仍可使用。切换输入停止旧采集或连接，清空旧目标；暂停、重置、低置信度保持与回中沿用第三阶段行为。
5. 先用固定模拟姿态走完真实中继链路，再接真实识别回调。可在手机页提供明确标注的测试发送模式，不能把模拟状态显示为摄像头识别。

当前继续驱动双上臂，不扩展前臂、躯干、腿部或 IK；没有新增交付 GLB。协议成功不代表真实手机姿态与物理关节完整验收。

## 4. 配对与访问控制

- 使用 `POST /api/rooms` 创建短期房间。服务器以密码学安全随机数生成至少 128 位房间 ID，以及各至少 256 位、彼此独立的 viewer/mobile 凭据。响应只发给创建者，禁止缓存。
- 手机配对链接只包含房间 ID 和 mobile 凭据，放在 URL fragment；不包含 viewer 凭据。页面读取后立即移除地址栏中的凭据，跨刷新恢复需要时只放本标签页 sessionStorage，不写日志或 localStorage。
- viewer 凭据只留在电脑会话；两种角色必须匹配各自凭据，mobile 凭据不能注册为 viewer。服务端保留凭据摘要并安全比较；房间 ID 本身不作为认证依据。
- WebSocket URL 固定为同源 `/ws`，凭据通过连接建立后的 hello 发送，不放查询字符串。生产只允许配置的 HTTPS Origin；开发例外使用显式白名单，不无条件接受任意 Origin。
- 创建 API 也校验 Origin、JSON Content-Type、体积和速率。HTTPS 生产不在明文 HTTP 端口创建房间或接受 upgrade；HTTP 继续跳转 HTTPS。
- 初版每房间一个 mobile、一个 viewer。同角色使用有效凭据重新注册可替换旧连接；先撤销旧连接资格再关闭它，并用连接代次检查阻止旧 close 回调误删新连接。
- 房间初始有效期 2 小时；双方离线 5 分钟后清理，以先到期限为准。房间/连接总量、单 IP 连接数、创建速率均设上限；初始参数在代码集中配置并通过测试覆盖边界。
- 房间只保存在内存。服务器重启后旧配对失效，返回明确的 `room_expired`，电脑提示创建新配对、手机提示重新打开链接；不无限重试失效凭据，也不显示虚假的已配对。
- 这是短期持有凭据的配对机制；拿到手机链接的人拥有该房间发送权限。支持结束配对并销毁房间，不实现账号体系或持久房间。

## 5. 共享协议草案

所有消息包含 `version: 1`，采用受限 JSON 文本。类型采用可判别联合，使用名称 `PoseMessage`，避免与采集 `PoseFrame` 混淆。

| 消息 | 方向 | 主要字段/约束 |
| --- | --- | --- |
| `hello` | 两端 → 服务端 | role、room、token；连接后 5 秒内完成，重复 hello 拒绝 |
| `ready` | 服务端 → 当前端 | room、role、connectionId、对端状态；收到后才进入已连接 |
| `pose` | mobile → 中继 → viewer | room、sessionId、seq、timestampMs、coordinateSpace、worldLandmarks |
| `capture` | mobile → 中继 → viewer | sessionId、状态（started/stopped/no_pose）；控制消息也限速 |
| `peer` | 服务端 → 另一端 | 角色上线/离线、连接代次、采集状态变化；不泄漏凭据 |
| `heartbeat/heartbeat_ack` | 应用心跳 | 随机探测 ID，用于浏览器侧发现无响应及统计往返时间 |
| `error` | 服务端 → 当前端 | 固定错误码、有限长度说明、是否可重试；不回显输入和凭据 |

姿态约束：

- `coordinateSpace` 固定为 `mediapipe-world`；33 个完整世界坐标关键点，类型复用 `PosePoint`。无人体时发送状态，不用空点数组伪装有效姿态。
- `x/y/z/visibility` 必须为有限数值，visibility 在 [0,1]；不把世界坐标错误限制到 [0,1]。为防极端数值影响下游，世界坐标各轴绝对值上限初定 100 米，测试验证拒绝边界。
- `seq` 是非负安全整数；`timestampMs` 是非负有限采集时间。同一采集会话中序号和时间严格递增；同会话重连不重置序号，重新启动采集生成新 sessionId。
- 服务端验证 room 与已认证房间一致；viewer、未注册端、旧连接代次都不得发送 pose。禁止二进制、未知消息类型和意外的大型字段。
- 默认最大消息 32 KiB（创建 API 更小）；消息、状态、心跳均限制频率。未知字段按严格 schema 拒绝，不能绕过大小限制塞入图像字符串。
- 服务端不记录完整消息、关键点或凭据；仅记录匿名汇总计数、错误码和必要运行事件。

## 6. 两端时钟、会话与映射适配

`Retargeter.accept` 用 `timestampMs` 与本地 nowMs 判断帧龄。不能直接将手机的 performance.now() 传入电脑求解器。

- 网络包保留手机采集 timestampMs 和 seq，用于同 session 内重复、倒退与顺序检查。服务端在注册连接身份下检查，电脑再校验一次。
- 每个新有效远程帧记录电脑本地接收时间。进入已有求解器时用本地单调时间和适配器本地递增序号构造 `RetargetFrame`；世界坐标原样传入，不镜像、不重复转换轴。
- sessionId 改变、mobile 连接代次改变、stop、断线、配对变化、切源时清空网络最新槽和映射旧输入；迟到的旧会话/旧连接事件不得重新驱动机器人。
- 接收后超过 1500ms 尚未消费的帧丢弃。依靠采集端即时发送、两端背压、心跳和本地最近收帧时间控制陈旧数据；本地到达时间不能证明网络传输前的数据年龄，不能声称已消除所有传输延迟。
- UI 可展示同端推理耗时、接收间隔和 RTT；没有跨设备时钟同步时，不显示伪精确的单向网络延迟。
- 长时间不收新帧沿用既有 250ms 保持后回中；重置仍暂停跟随，不因网络下一帧立即覆盖复位。

## 7. 连接、限速和背压

- 页面区分连接中、已连接、断开、错误，以及“已连接但对端未在线/未采集/无人体”；socket open 不等于注册成功或正在跟踪。
- 可恢复断线最多自动重试 6 次，延迟约 0.5/1/2/4/8/10 秒，附随机抖动。只有注册成功且稳定 30 秒后才重置重试预算，避免反复瞬断形成无限重连。
- 认证失败、房间过期、主动断开、配对被结束不自动重连；显示具体恢复操作。网络恢复事件只在剩余预算内提前重试，预算耗尽后提供手动重连。
- 发送目标 15 FPS，服务端姿态硬上限初定 20 FPS，使用允许少量短时突发的令牌桶；重复违规关闭连接。总体消息频率还需单独限制。
- 手机和中继检查 bufferedAmount，阈值初定 64 KiB。没有应用层历史队列，未发送帧被下一帧覆盖或直接丢弃；持续积压 5 秒关闭慢连接。已交给 socket 的字节不能撤回，不把“仅最新”描述为能删除底层缓冲。
- viewer 只保留一个最新有效帧槽，每次渲染最多消费一帧，不按历史消息逐帧播放。
- 服务端每 10 秒 ping，20 秒无 pong 清理；浏览器以应用心跳确认响应，超时退出已连接并重试。测试时注入短阈值，避免把测试建立在长时间等待上。
- pagehide、组件销毁、主动断开时关闭 socket、取消定时器与重连；摄像头隐藏停止后通知对端。后台暂停/恢复依照原采集行为，重新进入页面不偷偷开摄像头。
- 服务退出时先停止新连接并关闭全部 WS，清理心跳与房间，再关闭 HTTP/HTTPS；保留有界强制终止机制。

## 8. 运行包与部署设计

- 拟显式增加 `ws`、对应类型和 esbuild 开发依赖，实施时核对官方 API、Node 24 兼容性并锁定 lockfile；不依赖 Vite 的间接依赖恰好存在。
- 构建把 `server/relay.ts` 及共享协议打包到 `deploy/runtime/relay.mjs`；`deploy/server.mjs` 导入该产物。`ws` 保留为显式运行依赖，Node 内置模块保持外置。
- 构建脚本同时在 `deploy/runtime` 生成独立 package.json/lockfile，只声明经过锁定的 ws 生产依赖。暂不选用可选原生性能插件。
- 上传仍打包 `dist deploy`；新 release 目录内先执行 `npm ci --omit=dev --omit=optional --ignore-scripts` 安装这个小型运行包，再进行原子 symlink 切换和重启。实施前核对服务器 Node/npm；安装失败时不切换线上版本。
- 这样不将 Windows node_modules 直接传到 Linux，也不在服务器安装前端构建依赖。CI 对同一运行包执行独立安装及启动检查，防止本机根目录依赖掩盖漏包。
- 保留当前 443/TLS、证书续期、静态缓存、ACME 和 systemd 约束；更新服务描述，WSS 使用同端口 `/ws`，不额外公开裸 WS 端口。
- 开发环境增加明确的中继启动命令与 Vite `/ws`、`/api` 代理。手机联调使用可达的 HTTPS 地址；电脑 localhost 测试不能代替手机 LAN/公网测试。
- 发布后在现有服务器实际验证 HTTPS 创建房间、WSS 双端认证、模拟姿态转发、隔离和断线，核对 version.json/GitHub 提交/CI，再报告部署成功。保留 previous-release 回滚机制，不操作其他服务。
