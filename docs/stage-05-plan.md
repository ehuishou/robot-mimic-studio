### 帧与连接契约

- 网络坐标仍是 MediaPipe world；前摄镜像只影响预览，不交换解剖左右，不二次变换坐标。继续只驱动双上臂。
- sessionId 每次重新开始采集时更新；同会话 seq 和采集时间递增。旧连接代次或旧会话的迟到消息拒收；断线重连与摄像头重启分别处理。
- 当前实现已有 8 KiB 消息上限、20 次/秒服务端姿态上限、约 16 KiB 缓冲判断、世界坐标各轴绝对值 10 的边界。先保留并集中这些真实常量，不误把第四阶段准备稿的其他阈值视为已实现配置。
- 发送目标先配置为 15 次/秒，再以 15/20 次档位对比实测；不能提高发送率却忘记调整服务端限流预算。无人体通过状态表达，不反复发送空数组作为有效姿态。
- 手机发送需等注册成功；不建立历史帧队列。缓冲超限丢弃当次旧候选，持续积压退出连接；socket 已发送缓冲无法撤回，不能声称能清空 TCP 历史数据。
- 远端连接、对端在线、相机运行、人体有效、正在跟随是独立状态；不能把“已连中继”显示为“已连电脑/已识别”。推理与网络不得争用一个提示元素互相覆盖错误。
- 暂停不累积历史目标，恢复等待新观察；重置精确回初始姿态并保持暂停。停止/断线后不再刷新旧观察年龄，保留既有有限保持和安全回中行为。
- pagehide（包括 bfcache）、hidden、pageshow、切源和销毁分别测试；恢复不得自动启动摄像头，传输恢复策略需明确，不遗留 socket、重连定时器、推理实例或动画循环。
- 配对仍使用房间 ID 加独立角色凭据，房间码本身不是密钥。手机只获得 mobile 凭据，fragment 读取后从地址栏清除；刷新恢复策略限定标签页会话，不写 localStorage/日志，不持久化姿态。
- 房间码生成需验证字符集、熵和均匀取样；凭据只保留校验摘要，并为创建/连接设置有界资源策略。错误消息不回显凭据。
- 增加协议版本后，服务端与页面作为同一 release 发布；旧页面提示刷新/重新配对，不把不兼容协议默默解释成有效帧。

## 6. 性能测量与报告口径

| 指标 | 测点与统计 |
| --- | --- |
| 手机推理耗时/推理 FPS | `runner.detect` 前后同端单调时钟；排除模型加载/预热后独立统计中位数、P95与样本数，记录实际视频分辨率 |
| 手机发送与中继转发 Hz | 手机统计实际 send 成功调用数，中继统计符合条件的实际转发数，各自按单调时间窗口汇总；分别记录限频、无人体、过期、背压、校验失败计数 |
| 电脑接收到骨骼应用 | 有效帧进入最新槽至本帧 `retargeter.update` 完成，同端单调时钟配对；被覆盖而未应用的帧不能计为零耗时 |
| 渲染 FPS | 沿用 Three.js 实际渲染循环窗口，不把推理次数、收包次数当渲染帧率 |
| 应用确认往返耗时（代理指标） | 电脑骨骼应用后仅反馈 session/seq 确认；手机以同一时钟计算从推理开始到确认到达的时间，覆盖推理、发送、应用和额外回程；不称为真实单向/视觉延迟 |
| 真实端到端动作延迟 | 真机情况下用同一录像同时记录人体与电脑显示，逐帧标定动作事件及机器人首次对应响应，记录录像帧率、事件定义、匹配数、帧量化误差和人工标注误差；若改用时钟校准，必须报告偏差/漂移及不确定度 |

- P95 不超过 200 ms 是第五阶段验收目标，不是当前实测结果。网络 RTT、应用确认往返、分段耗时与视觉动作延迟分列；不得用代理指标替代真实端到端达标证据。
- 明确预热时间、十分钟计时区间、丢失/未匹配事件、无人体时长和掉线时段。除了有效样本分位数，还需报告丢帧和无响应比例，不能只留下成功帧粉饰延迟。
- 使用有限长度采样/固定统计桶，记录采样策略，原始日志不包含视频、token 或关键点历史。按浏览器可观测能力记录内存，不把 JS heap 当作全部 GPU/WASM/进程内存。
- 默认不引入 Worker 或降关键点精度；先用测量定位主线程阻塞。低性能机按证据降低发送频率/推理频率，保持 UI 可操作和安全停止，并展示降级状态。

## 11. 手机识别初始断连修复（2026-10-24）

- 现场反馈：手机进入配对房间后，启动识别即像退出；电脑端机器人没有动作。真实手机现场日志尚未取得，因此不把代码定位当作唯一根因。
