# MediaPipe + Three.js 机器人动作模仿项目：后续开发指南

本文档配合 Codex 使用。项目第一阶段已经有一条独立任务：搭建 Three.js
机器人展示页。完成并验收后，再按本文档顺序逐步推进。

## 开发顺序

1.  `02_手机端姿态识别.md`：在手机浏览器中运行
    MediaPipe，显示摄像头画面和人体关键点。
2.  `03_机器人动作映射.md`：先使用模拟关键点驱动机器人，再将人体关键点映射到模型骨骼。
3.  `04_WebSocket通信.md`：建立 Node.js WebSocket
    中继，连接手机端和电脑端。
4.  `05_端到端集成与验收.md`：把所有模块串联，做延迟、稳定性、异常和隐私验收。

## 使用原则

-   每次只把一个阶段的任务交给 Codex，不要一次性要求它完成所有阶段。
-   开始前要求 Codex 阅读仓库中的
    `README.md`、`AGENTS.md`（如果存在）和相关源码。
-   不要让 Codex 猜测 GLB 模型骨骼名称。必须从实际模型遍历结果中确认。
-   每个阶段都要运行类型检查、构建和适用的测试；不能执行的测试必须明确标注。
-   阶段验收未通过前，不进入下一阶段。
-   保留已有实现；修改前先检查当前代码，避免无故覆盖文件。
-   不要把摄像头原始图像发送到 WebSocket；默认只传关键点数据。

## 建议的阶段交付物

每阶段结束时，要求 Codex 汇报： 1. 修改或新增的文件。 2. 本地启动命令。
3. 实际执行的检查与结果。 4. 已知问题和暂时未实现的部分。 5.
下一阶段依赖的接口、数据结构和前置条件。

## 推荐工作流

先完成当前阶段，再审查差异：

``` bash
git status
git diff --stat
git diff
```

确认无误后再提交：

``` bash
git add .
git commit -m "完成阶段名称"
```

不要在尚未理解改动时盲目接受大规模重构。
